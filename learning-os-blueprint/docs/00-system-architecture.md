# Personal Learning OS: System Architecture & Context

## 🎯 1. Project Goal
Eliminate "AI tooling FOMO" by providing an all-in-one, dynamic, personalized learning environment integrated directly into Obsidian. The system adapts to the user, remembers preferences per subject, tracks nuanced progression, and autonomously evolves its own capabilities through multi-agent loops.

## 🧱 2. System Architecture

The application operates on a split architecture: an Obsidian Frontend for UI/UX and File Operations, and a Local Python Backend for heavy AI orchestration.

### A. Frontend: Obsidian Plugin (TypeScript + React/Svelte)
*   **Role:** The client, UI, and single source of truth for file modifications.
*   **Settings:** Accepts custom OpenAI-compatible endpoints and API keys (to support model pooling like AIClient2API) and the local Python server URL.
*   **UI Components:** Sidebar panes for the "Preferences Chatbot," interactive React/Svelte widgets embedded inside markdown files (e.g., feedback blocks for skills), and toggle switches for preferences.
*   **File Writer:** To prevent file corruption, the Python server sends generated content to the plugin, and the plugin uses Obsidian's native `app.vault.modify()` to safely write to Markdown and Canvas files.

### B. Backend: Local Python Server (FastAPI)
*   **Role:** The "Brain" of the system. Run manually via terminal.
*   **Orchestration:** Hosts multi-agent workflows (using tools like LangGraph/CrewAI/AutoGen).
*   **Endpoints:** Exposes local endpoints (e.g., `/generate`, `/chat`, `/evolve-skill`) to the Obsidian plugin.
*   **LLM Routing:** Uses the OpenAI-compatible configuration passed from the plugin to route requests to the user's chosen model pool.

### C. Database: The Obsidian Vault
*   **Knowledge Context:** `_subject-context.md` inside each subject folder dictates goals, past exams, and active preferences.
*   **State Management:** Hidden folder (e.g., `/.obsidian/learning-os-data/`) stores JSON configurations for agent states and skills.
*   **Metadata:** Uses YAML Frontmatter on topic notes to silently track mastery levels and struggle areas.

## ✨ 3. Core Features & Dynamic Preferences

### The Progression Map
*   Uses native Obsidian Canvas (`.canvas` files).
*   The plugin programmatically generates and updates a visual node map of topics.
*   Nodes are color-coded (e.g., Red to Green) based on mastery data parsed from YAML Frontmatter.

### Dynamic Preferences Engine
The system utilizes a central `learning-artifact-generator.md` configuration. Users can toggle qualitative features without reprompting. Examples include:
*   **Socratic Mode:** The AI generates guiding questions instead of direct answers.
*   **The Metaphor Engine:** Maps abstract concepts to the user's specific hobbies/interests.
*   **Visual Bias:** Forces the generation of `mermaid.js` diagrams and charts over text.
*   **Spaced Repetition Integration:** Auto-generates Anki-style flashcards at the bottom of notes.
*   **Feynman Technique Evaluator:** An interactive UI block where the student explains the concept; the AI grades it for gaps.
*   **Confidence Highlighting:** Visually highlights text based on whether it is explicitly found in the student's materials or generated by external AI assumptions.

### Agentic Skill Evolution (The Pre-dedicated Agent Loop)
A system to transform abstract user requests into reusable, perfected skills.
1.  **Request:** User asks for a complex feature (e.g., "Add interactive visual math models").
2.  **Sub-Agent Spawning:** The Preferences Chatbot spins up a Research Agent (to figure out how to implement it in Obsidian) and a Reasoning Agent (to build the prompt).
3.  **Unrefined Skill:** A new skill is created (e.g., `visual-math.json`) and added to the UI with a status of "Unrefined".
4.  **Feedback Loop:** When used, an interactive widget asks for micro-feedback (e.g., 1-5 scale, text input).
5.  **Mastery:** After sufficient positive feedback loops, the Python backend optimizes the prompt and promotes the skill to "Mastered".

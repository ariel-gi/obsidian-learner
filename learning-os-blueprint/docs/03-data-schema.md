# Data Schema & Storage Blueprint

## 1. Overview
Since we are using Obsidian, our database is entirely composed of local files. This document details exactly how data is structured and stored within the user's vault to ensure consistency between the TypeScript frontend and the Python backend.

## 2. Vault Folder Structure
```text
My Obsidian Vault/
├── .obsidian/
│   ├── plugins/
│   │   └── learning-os-plugin/     # The compiled TS frontend
│   └── learning-os-data/           # Hidden system state folder
│       ├── system_config.json      # Global app settings (if not in data.json)
│       └── skills/
│           ├── visual_bias.json    # Pre-built skill
│           ├── metaphors.json      # Pre-built skill
│           └── user_created_1.json # Unrefined/Mastered generated skill
├── Calculus/                       # A Subject Folder
│   ├── _subject-context.md         # The Master Context File
│   ├── ProgressionMap.canvas       # Visually tracks mastery
│   ├── Lectures/
│   ├── Concepts/
│   │   ├── Derivatives.md          # An generated artifact
│   │   └── Limits.md               # An generated artifact
└── Linear Algebra/                 # Another Subject Folder
    └── ...
```

## 3. Data Formats

### 3.1. The Subject Context (`_subject-context.md`)
This file is the "Brain" of the subject. It is injected into the LLM context for *every* artifact generation in this folder.
```yaml
---
subject_name: Calculus
goals: ["Pass the AP Exam", "Understand intuition behind formulas"]
exam_date: 2026-11-15
---
# Current Gaps
I am struggling heavily with the Chain Rule.

# Approved Materials
(Links to PDFs or other markdown notes in the vault)
[[Lecture_1_Limits]]
```
- **Read by:** Obsidian Plugin (parses text/YAML) -> Sent to Python.

### 3.2. Topic Artifacts (e.g., `Derivatives.md`)
The actual learning notes generated by the AI. We rely heavily on YAML Frontmatter to invisibly track progress without cluttering the student's reading experience.
```yaml
---
topic: Derivatives
status: in-progress
mastery_level: 45      # 0-100 scale. Read by the Canvas Generator.
struggle_areas: ["Trigonometric derivatives"]
prerequisites: ["Limits"] # Used to draw arrows in the .canvas map.
---
# Derivatives
(The AI generated content here...)

# Interactive Widgets (Rendered by Obsidian Markdown Post Processors)
````feynman-evaluator
{ "concept": "Derivatives", "strictness": "high" }
````
```

### 3.3. Skill Definitions (JSON inside `/.obsidian/learning-os-data/skills/`)
Skills dictate *how* the AI acts. They are essentially modular system prompts with metadata.
```json
{
  "skill_id": "metaphor_engine",
  "name": "Metaphor Engine",
  "description": "Explains complex concepts using the user's hobbies.",
  "status": "mastered",  // "unrefined" or "mastered"
  "is_active": true,     // Toggled via the Obsidian UI
  "system_prompt": "You are a metaphor engine. The user enjoys basketball. Always relate mathematical or logical concepts to basketball terminology or gameplay strategies.",
  "feedback_score": 4.8,
  "iterations": 12
}
```

## 4. The Canvas File Format (`.canvas`)
Obsidian stores `.canvas` files as plain JSON. Our `canvasManager.ts` will programmatically update this.
```json
{
  "nodes": [
    {
      "id": "node_derivatives",
      "type": "file",
      "file": "Calculus/Concepts/Derivatives.md",
      "x": 0,
      "y": 0,
      "width": 400,
      "height": 400,
      "color": "3" // "3" = Green in Obsidian, mapped dynamically from mastery_level = 85
    },
    {
      "id": "node_limits",
      "type": "file",
      "file": "Calculus/Concepts/Limits.md",
      "x": 0,
      "y": -500,
      "width": 400,
      "height": 400,
      "color": "4" 
    }
  ],
  "edges": [
    {
      "id": "edge_1",
      "fromNode": "node_limits",
      "fromSide": "bottom",
      "toNode": "node_derivatives",
      "toSide": "top"
    }
  ]
}
```

## 5. Development Strategy for Data Storage
1. **Frontend:** We must build robust `YAML Frontmatter` parsers in TypeScript. Obsidian provides `app.metadataCache`, but modifying it programmatically requires careful regex or using `app.fileManager.processFrontMatter()`.
2. **State Sync:** The Python backend is *stateless* regarding skills. Whenever Obsidian sends a request to Python, it must package and send the JSON of the currently `active` skills.
3. **Canvas Updates:** The `canvasManager.ts` should run on a debounce (e.g., every 5 minutes, or manually via a button) to prevent constant file writes while the student is typing.
